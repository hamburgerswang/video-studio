# video-studio 项目总结

> 整理日期：2026-11-03，基于 `main` 分支 `04f51ce`。

## 1. 项目定位

基于 Remotion（用 React 渲染视频）的「分享视频工作台」。一个仓库维护多支技术分享视频：公共能力放在 `src/framework/`，每支视频是 `src/videos/<主题>/` 下的独立目录。视频自带中文配音（macOS `say`，语音 Tingting）、合成音效和字幕。

## 2. 技术栈

- Remotion 4（`remotion`、`@remotion/cli`、`@remotion/transitions`）
- React 19 + TypeScript 5
- Python 3 脚本：生成配音、合成音效（纯标准库，不依赖 ffmpeg）
- Node 脚本：新建主题的脚手架
- 运行环境：Node 18+、Python 3、macOS

## 3. 目录结构

```
video-studio/
├── scripts/
│   ├── gen_sfx.py        # 合成共享音效 whoosh / ding / ding-bright / type
│   ├── gen_audio.py      # say 生成配音 → 测时长 → 写回 audioMeta.json
│   └── new_video.mjs     # 基于 template 新建主题目录
├── public/audio/
│   ├── sfx/              # 共享音效
│   └── <主题>/narration/ # 各主题配音 wav，按主题隔离
└── src/
    ├── index.ts / Root.tsx   # 遍历 VIDEOS，为每支视频注册 Composition
    ├── framework/            # 公共引擎（约 900 行）
    │   ├── types.ts          # VideoDef / SceneEntry / videoDuration
    │   ├── Video.tsx         # TransitionSeries 串联场景 + 淡入淡出
    │   ├── theme.ts / palette.tsx   # 结构色 + 主题色 makePalette / usePalette
    │   ├── components/       # Background、SceneHeader、Captions、SceneAV、ui
    │   └── scenes/           # 6 种场景原型 + _Blank 骨架
    └── videos/
        ├── index.ts          # 主题注册表 VIDEOS
        ├── llm-cache/        # LLM 缓存机制
        ├── browser-journey/  # 从输入网址到渲染成功（含 9 个专属场景）
        └── template/         # 模板示例片
```

## 4. 核心机制

### 4.1 VideoDef 是唯一真相源
每支视频导出一个 `VideoDef`（`src/framework/types.ts`），字段为 `id`、`title`、`scenes`、`narration`、`audioMeta`，可选 `palette`、`fps`（默认 30）、`width`×`height`（默认 1920×1080）。`Root.tsx` 用闭包 `() => <Video def={def} />` 传入 def，因为场景是 React 节点，不能走可序列化的 `defaultProps`。

### 4.2 配音决定时长
1. `narration.json` 写每个场景的旁白 `text` 和字幕 `captions`。
2. `gen_audio.py` 调 `say` 生成 wav，算出帧数 `HEAD_PAD(12) + ceil(秒数×30) + TAIL_PAD(22)`，写入 `audioMeta.json`。
3. `Video.tsx` 按 `audioMeta` 给每个场景分配帧数。相邻场景有 18 帧过渡重叠，总帧数 = 各场景帧数之和 − (场景数−1)×18。缺少元数据的场景默认 150 帧。

改了文案必须重跑 `npm run audio <主题>`，否则音画和字幕会错位。

### 4.3 场景与音画叠加
- `SceneAV.tsx` 给每个场景叠加配音（从第 12 帧开始）、过场音 `whoosh`（首个场景除外）、节点音效 `sfx`，以及字幕。
- 字幕按字数加权，铺在 `总帧数 − HEAD_PAD − TAIL_PAD` 的窗口内。
- `HEAD_PAD` / `TAIL_PAD` 在 `gen_audio.py` 和 `SceneAV.tsx` 各定义一次，改动时要两处同步。

### 4.4 场景原型（`framework/scenes/`）
- `TitleScene`：开场标题
- `ListScene`：要点列表
- `PipelineScene`：流程链路（箭头串联阶段，可带结论横幅）
- `ExchangeScene`：交互 / 通信过程
- `CodeScene`：代码卡片
- `RecapScene`：回顾总结
- `_Blank.tsx`：自定义场景的骨架

### 4.5 配色
`palette: makePalette({ accent, accent2 })` 整体换肤。背景、文本、字体等结构色全仓库共享。场景内用 `usePalette()` 取色。
## 5. 现有视频

时长按 `audioMeta.json` 和 30fps 推算。

- **llm-cache**「LLM 缓存机制」：9 个场景，3584 帧，约 2 分钟。全部使用框架原型，青→靛配色（`#22d3ee` / `#818cf8`）。内容依次是为什么要缓存、KV Cache 与 Prompt Caching 两层、分块 + 链式哈希存储、前缀匹配规则、首次写入与再次命中、四个命中条件、"稳定在前、动态在后"的实践法则、回顾。
- **browser-journey**「从输入网址到渲染成功」：9 个场景，2542 帧，约 85 秒。全部为专属场景（`browser-journey/scenes/`），依次是 URL 解析、DNS、TCP、TLS、HTTP 请求、服务端处理、页面渲染，加上开场和结尾。默认配色。
- **template**「模板示例片」：6 个场景，1497 帧，约 50 秒。演示各原型的用法，也是 `npm run new` 的复制来源。

## 6. 常用命令

```bash
npm install                     # 安装依赖（首次会下载无头 Chromium）
npm run dev                     # Remotion Studio 预览
npm run audio [主题]            # 生成音效 + 配音（不带参数 = 全部主题）
npm run new <id> "<标题>"       # 新建主题
npx remotion render <id> out/<id>.mp4   # 导出单支视频
npm run render:all              # 导出 browser-journey 和 template
```

## 7. 新增一支视频

1. `npm run new my-topic "我的标题"`
2. 手动在 `src/videos/index.ts` 中 import 并加入 `VIDEOS`（脚手架不会改这里）
3. 编辑 `narration.json` 和 `scenes.tsx`，两者的场景 id 必须一一对应
4. `npm run audio my-topic`
5. `npm run dev` 预览，或 `npx remotion render my-topic out/my-topic.mp4` 导出

## 8. 现状与待注意事项

- **没有 lint、测试或 typecheck 脚本**。只能靠 Studio 预览、真实导出，或手动 `npx tsc --noEmit` 校验。
- **`render:all` 漏了 llm-cache**。`package.json` 只导出 browser-journey 和 template，也没有 `render:llm-cache` 快捷命令。
- **README 目录结构没列出 llm-cache**，与仓库现状不一致。
- **留白常量重复定义**：`HEAD_PAD` / `TAIL_PAD` 在 Python 和 TSX 两处硬编码，靠人工保持同步。
- **配音绑定 macOS**：`say` 只有 macOS 有，Linux / CI 上无法重新生成配音。已生成的 wav 已提交到仓库，导出视频不受影响。
- **新主题要手动注册**：`new_video.mjs` 生成目录后不会改 `videos/index.ts`。
