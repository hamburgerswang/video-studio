# 场景描述文件格式

一个描述文件就是一支视频，文件里写了哪些场景就生成哪些。写好后一条命令出片：

```bash
npm run make <描述文件.md> <id> "<标题>"
# 例：npm run make md/场景描述-示例.md video-flow "三分钟学会做视频"
```

这条命令会依次完成：生成 `src/videos/<id>/` → 注册到 `src/videos/index.ts` → 生成配音 → 导出 `out/<id>.mp4`。

- `id` 只能用小写字母、数字和连字符，同时作为视频编号和音频目录名。
- `标题` 是视频标题。title 场景和 recap 场景没写「标题」时，也用它。
- 改了描述文件，用同一个 id 再跑一次即可覆盖。手写的视频目录不会被覆盖，脚本会报错退出。
- `<!-- -->` 里的内容会被忽略，可以写备注。

## 文件结构

```markdown
# 任意标题（只给人看，不解析）

配色: #a78bfa, #f472b6        ← 可选，两个颜色，不写用默认配色

## 场景id | 类型
字段: 值
- 列表项
旁白: 这一段的配音文案
字幕: 第一句 | 第二句
音效: ding@78                 ← 可选
```

- 每个场景以 `## 场景id | 类型` 开头，场景 id 只能用字母、数字、`_`、`-`，不能重复。
- 每个场景必须有「旁白」。「字幕」用 `|` 分隔多句，不写就整段旁白当字幕。
- 「音效」写 `名称@帧`，多个用逗号分隔。帧数从场景开头算，30 帧 = 1 秒。可用名称：`whoosh`、`ding`、`ding-bright`、`type`。
- 第几步 / 共几步（step / total）自动计算，只算 list、code、pipeline、exchange 四种。
- 冒号中英文都可以。

## 六种场景类型

### title：开场标题
- `小标题`：标题上方的小字，可选
- `标题`：主标题，用 `\n` 换行，不写就用命令里的标题

### list：要点列表
- `标题`（必填）、`副标题`
- 列表项：`- 名称 | 说明`

### code：代码卡
- `标题`（必填）、`副标题`、`文件名`
- 代码写在 ``` 代码块里，逐行浮现

### pipeline：流程
- `标题`（必填）、`副标题`、`结论`（底部横幅）
- 列表项：`- 图标 | 名称 | 说明`，也可以省略图标写成 `- 名称 | 说明`

### exchange：两端交互
- `标题`（必填）、`副标题`、`结论`
- `左`、`右`（必填）：`图标 名称`，用空格隔开，如 `左: 💻 客户端`
- 列表项是消息：`- -> 内容` 表示左到右，`- <- 内容` 表示右到左

### recap：回顾
- `标题`、`副标题`
- 列表项：每一项是一个步骤名
